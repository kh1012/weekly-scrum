# 성능 최적화 적용 완료 보고서

## 실행 일시

2026-01-10

## 최적화 목표

`/my` 페이지의 초기 로딩 속도를 30-50% 개선

## 적용된 최적화

### 1. Layout 최적화 (src/app/(scrum)/layout.tsx)

**문제점**

- Supabase 클라이언트 2회 생성
- 사용자 정보 2회 조회
- 프로필 조회 중복
- 독립적인 쿼리들이 순차적으로 실행 (menuSettings, menuViewCounts, menuStats, menuNewCounts, supabaseData)

**개선 내용**

- Supabase 클라이언트를 한 번만 생성하여 재사용
- 사용자 정보를 한 번만 조회
- 프로필 조회를 한 곳으로 통합
- 독립적인 6개 쿼리를 `Promise.allSettled`로 병렬 실행
- 에러 처리를 통일하여 안정성 향상

**예상 개선 효과**

- 쿼리 시간: 500-1500ms → 200-500ms (60-70% 단축)

### 2. Page 최적화 (src/app/(scrum)/my/page.tsx)

**문제점**

- Layout에서 이미 조회한 프로필을 다시 조회
- 프로필 조회와 메트릭 조회가 순차적으로 실행

**개선 내용**

- 프로필 조회와 메트릭 조회를 `Promise.all`로 병렬 실행
- Layout과의 중복 제거는 아키텍처 제약으로 인해 병렬화로 대체

**예상 개선 효과**

- 쿼리 시간: 100-200ms 단축

### 3. getPersonalDashboardMetrics 최적화

**문제점**

- Snapshot, Plan, Usage 메트릭 쿼리가 순차적으로 실행
- 추가 데이터 쿼리들도 순차적으로 실행
- 총 8-12개의 쿼리가 직렬로 실행됨

**개선 내용**

**Phase 1: 기본 메트릭 병렬화**

- Snapshot, Plan, Usage 메트릭을 `Promise.allSettled`로 병렬 실행 (3개 쿼리)
- 각 섹션의 초기 쿼리를 동시에 시작

**Phase 2: 추가 데이터 병렬화**

- 최근 엔트리, 도메인 분포, 주차별 추이 쿼리를 병렬 실행 (3개 쿼리)
- 총 6개의 독립적인 쿼리를 2단계로 나누어 병렬 실행

**예상 개선 효과**

- 쿼리 시간: 1000-2000ms → 400-800ms (50-60% 단축)

### 4. menuStats 최적화

**문제점**

- 6-8개의 쿼리가 순차적으로 실행
- userId가 있을 때 추가 쿼리들도 순차 실행

**개선 내용**

- 기본 쿼리 6개를 `Promise.allSettled`로 병렬 실행
- userId가 있을 때 추가 쿼리 2개를 기본 쿼리에 포함하여 병렬 실행
- Alignment 관련 쿼리 2개를 병렬 실행

**예상 개선 효과**

- 쿼리 시간: 300-600ms → 150-250ms (50-60% 단축)

## 전체 예상 개선 효과

### 이전 예상 로딩 시간

- 적은 데이터: 300-700ms
- 중간 데이터: 700-2000ms
- 많은 데이터: 2000-4000ms

### 최적화 후 예상 로딩 시간

- 적은 데이터: 200-400ms (약 40% 개선)
- 중간 데이터: 400-900ms (약 50% 개선)
- 많은 데이터: 900-1800ms (약 50% 개선)

## 적용된 기술

1. **Promise.all / Promise.allSettled**
   - 독립적인 비동기 작업을 병렬로 실행
   - allSettled를 사용하여 일부 쿼리 실패 시에도 다른 쿼리 결과 활용

2. **중복 제거**
   - 동일한 데이터를 여러 번 조회하지 않도록 개선
   - Supabase 클라이언트 재사용

3. **에러 처리 강화**
   - 각 쿼리의 성공/실패 상태를 개별적으로 처리
   - 부분적인 실패에도 페이지가 정상 동작

## 성능 측정 방법

브라우저에서 직접 측정할 수 있는 도구 제공

**사용 방법**

```
http://localhost:3000/measure-performance.html
```

1. 측정할 페이지 경로 입력: `/my`
2. 반복 횟수 입력: `100`
3. "테스트 시작" 클릭
4. 결과 확인 및 JSON 저장

**측정 항목**

- 전체 로딩 시간
- TTFB (서버 응답 시간)
- DOM 파싱 시간
- 완전 로딩 시간
- 시간대별 분포
